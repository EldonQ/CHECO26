## 一、为什么需要这份复核

项目自带的校验器（`11_validate.R` 的 V1–V6、`check_clcd_year.R`）在本会话中已被发现
**五处"空转"缺陷**：

| 缺陷 | 表现 |
|---|---|
| V4 从未被执行 | 报 PASS 但代码路径不可达 |
| V5 从诞生起没检查过组成恒等式 | 变量名写错，恒等式比对恒为 0 次 |
| F 组读了模板而非数据层 | 全部 NA → `worst` 恒为 0 → PASS |
| 硬编码窗口落在国界外 | 0 次比较 → PASS |
| D 组测试了已被替换为 0 的变量 | 永远 PASS |

**共同特征：检查跑完了、报 PASS 了、但实际比较次数为 0。**

所以本报告刻意做两件事：

1. **不使用项目内任何 helper**（`_bootstrap.R`、`raster_stats()`、`file_nodata()`、
   `count_layers()` 一律不用），只用 `terra` + base R 从磁盘重算。
2. **每一条断言都必须报出比较次数**，并在断言中要求次数达到预期下限。

## 三、复核过程中发现并修掉的 4 个检查器自身缺陷

第一轮运行报 **PASS 10 / FAIL 4**，四个 FAIL **全部是检查脚本的错，数据本身正确**。

### 3.1 MANIFEST 与磁盘双向一致 — 路径前缀

`MANIFEST.csv` 的 `relpath` 是相对 `data/` 的路径，以 `covariates/` 开头；
而 `list.files(COV)` 返回的路径已经不含这层。两边直接比 `setdiff` 恒为空集，
于是"磁盘多 21,110 / 清单多 21,110"——看起来像全不一致，实际是格式没对齐。

**修法**：给磁盘侧补回 `covariates/` 前缀。
**结果**：双向差集都是 0。

### 3.2 mask 外像元存储值 — 把 terra 的 NA 转换当成错误

`terra::values()` 读到声明为 −9999 的 nodata 时会**自动转成 NA**，这是正确行为。
我原来断言"应读出 −9999"，必然失败。

**修法**：改为断言"读出 NA"，并加一条更强的检查——
**整层 NA 像元数必须等于 mask 的 0 值数**（10,255,072 = 10,255,072）。

### 3.3 mask 有效像元 — 用错了判定口径

`mask_china.tif` 是 **INT1U、值域 0/1、声明 nodata=255 但实际没有一个 255**。

| 口径 | 结果 |
|---|---:|
| `!is.na(mask)` | 19,745,382（全部像元，因为 nodata 不在数据里）|
| **`mask == 1`** | **9,490,310** ✅ |

所以必须用 `== 1`。"有效像元"在这个掩膜上的含义是"国界内"，
不是"非 nodata"。

### 3.4 SHA-256 — 路径重复拼前缀

`file.path(COV, "covariates/glo/...")` 变成 `.../covariates/covariates/glo/...`，
`file.exists()` 全部 FALSE，于是**比较 0 层却报 PASS**。

这条正是"空转检查"的活样本：如果不是强制输出比较次数，
它会以"PASS"的形态混过去。

**修法**：用 `dirname(COV)` 作基准。修好后 8 个哈希全部匹配。
